A wiki kept by a model drifts, unless something keeps the books

Asking Claude to maintain a knowledge base works for a week. Then a page is overwritten by an older copy, a source gets "tidied up", a link points nowhere, and you cannot tell what changed when. mindyard splits the work: the model reasons about your notes, the server enforces the rules.

Lost updates

Two sessions, or you in your editor and Claude in a chat, edit the same page. The last writer silently wins.

Rewritten sources

The raw material you clipped is "improved" until nobody knows what the original said.

No history

Files edited in place leave no trace of what the model did, or of how to undo it.

How the mindyard MCP server works

Your wiki is a folder of Markdown files in a git repository. mindyard exposes it to your MCP client through six tools. No model runs on the server: it executes and records, it does not reason.

Your vault

Markdown pages, [[wikilinks]], YAML frontmatter, a wiki.yaml of rules. A git repository you own, Obsidian-compatible.

→

mindyard

list_wikis, read_page, list_pages, search_wiki, get_lint_report and one write path: write_batch.

→

Your client

Claude.ai, Claude Desktop, Claude Code or any MCP client over streamable HTTP.

Guarantees for a personal wiki in git

Each of them is enforced by the server and covered by tests. The model cannot talk its way around them.

Every write is one git commit

A batch of edits is validated whole, then applied in a single commit. If anything fails, nothing is written.

d9adce2 Add marigold, a companion for the tomato bed
 4 files changed, 17 insertions(+), 1 deletion(-)

No lost updates

Changing a page requires the version you read. If it moved since, the edit is refused and the model has to read it again.

'wiki/plants/tomato.md' changed on disk since you read it

Write zones

Sources in raw/ are create-only. The index, log and schema cannot be deleted. wiki.yaml is read-only for the model.

files under raw/ are create-only

The protocol travels with the server

The editorial method reaches the model through MCP instructions and tool descriptions. Clients without any skill or custom prompt still follow it.

Works with Claude.ai

Google sign-in (OAuth) for Claude.ai custom connectors, with an allowlist of accounts. Bearer tokens for Claude Code, Claude Desktop and scripts.

A deterministic linter

Broken links, orphans, frontmatter, and the rules your wiki.yaml declares: required fields, closed status lists, statuses implied by dates.

plant:
  required: [title, family]
  status: [planned, growing, harvested]

What a session looks like

A real exchange with the demo vault, an imaginary community garden. Tool calls are shortened; outputs are verbatim.

You

Volunteers say marigolds keep aphids off the tomatoes. Add that to the garden wiki.

Claude

I'll create a Marigold page, link it from Tomato, and add it to the index and the log, in one batch. Shall I go ahead?

You

Go.

Claude, through mindyard

Reads each page it will change, with its version:

read_page(wiki="garden", path="wiki/plants/tomato.md", raw=True)
→ version 45ab73651af99a31

Sends the whole change as one batch:

write_batch(wiki="garden", message="Add marigold, a companion for the tomato bed", edits=[
  {op: "create",  path: "wiki/plants/marigold.md", ...},
  {op: "replace", path: "wiki/plants/tomato.md", expected_version: "45ab73651af99a31", ...},
  {op: "replace", path: "index.md", ...},
  {op: "replace", path: "log.md", ...}])
→ {"commit": "d9adce2", "applied": [4 ops]}

A later edit built on the old version is refused, instead of erasing this one:

'wiki/plants/tomato.md' changed on disk since you read it (your version
45ab73651af99a31 is stale). Re-read the page to get its current content and
version, then rebuild the edit on that content and retry.
Your terminal
$ git log -1 --stat

Quickstart: a Claude knowledge base in three commands

You need Python 3.12 or later and uv. pip install mindyard works too.

  1. Create a vault. Drop --demo for an empty one.

    uvx mindyard init ./data/vaults/garden --demo

  2. Serve it. Without authentication, mindyard only listens on loopback.

    MINDYARD_DATA_ROOT=./data uvx mindyard serve

  3. Connect Claude Code.

    claude mcp add --transport http mindyard http://127.0.0.1:8787/mcp

Claude.ai

Deploy behind TLS with MINDYARD_AUTH=google and an allowlist of accounts, then add the URL as a custom connector.

Claude Desktop and scripts

MINDYARD_AUTH=bearer, then mindyard token new laptop prints a token once. Only its hash is stored.

Docker

A compose.example.yaml ships with the repository. Put a TLS reverse proxy in front.

Questions

Does mindyard send my notes anywhere?

No. mindyard runs on your machine or your server and stores everything in a git repository you own. Your notes reach only the MCP client you connect, such as Claude.

Does mindyard run a language model?

No. The model stays in your client. The server executes and records: it validates edits, commits them and lints the vault, without reasoning about the content.

Is it compatible with Obsidian?

Yes. A vault is plain Markdown with [[wikilinks]] and YAML frontmatter. Open it in Obsidian or any editor; edits made there are protected by the same version check as the model's.

Which clients work with mindyard?

Any MCP client over streamable HTTP: Claude.ai through a custom connector with Google sign-in, Claude Desktop and Claude Code with a bearer token, and other MCP clients.

Can I keep several wikis?

Yes. Every directory under vaults/ holding a wiki.yaml is served as its own wiki, and the model picks one per operation.

What does it cost?

Nothing. mindyard is free software under the AGPL-3.0, free to self-host. A hosted version is being considered for people who would rather not run a server.
